## 0. 요약 (5줄)

1. **포지셔닝**: "토익 RC 점수가 자격 요건인 사람에게, 시험일까지 RC만 올리는 웹 학습 서비스. 문항을 더 많이 주는 대신 왜 틀렸는지 가르치고, 예상 점수를 범위와 근거로 보여 준다."
2. **가치 제안 3개**는 W1(시험일까지 RC 플랜) · W2(틀린 이유까지 보여 주는 검수 문항) · W3(부풀리지 않는 범위형 예측)에 1:1로 대응한다. 브랜드 톤은 "담백하고, 숫자는 보수적으로, 약속은 작게".
3. **메시지 우선순위**는 vision.md 7장을 따른다: P1 공무원·공기업 → P3 승진 요건 직장인 → P2 토익 받는 기업·졸업 인증 → P4 고득점(대기 등록만). 스피킹으로 바꿀 수 있는 대기업 공채 일반 지원자에게는 광고비를 쓰지 않는다.
4. **대기자 모집**: 무료 RC 진단 "우선 이용권"을 리드 마그넷으로 하는 랜딩 1장 + 공무원·공기업 커뮤니티, 대학 취업센터, 검색, 블로그/유튜브/인스타. S2에 W1 메시지 A/B("RC만, 시험일까지" vs "토익 800 달성")를 돌린다. 목표 [제안]: 클로즈드 베타(S6) 전 대기자 1,000명, 세그먼트 1·2 비중 50% 이상.
5. **하지 않을 것**: 점수 보장, "1위"·"최초"·"가장" 같은 근거 없는 최상급, 조작·위장 후기, 경쟁사 비방. 해커스가 2023년 후기 조작(과징금 약 7.8억 원, 잠정)과 "1위" 기만 광고(2.86억 원)로 공정위 제재를 받은 사례 [사실, competitor-complaints.md 유형 11]를 우리 운영 원칙의 반면교사로 삼는다.

## 1. 포지셔닝

### 1.1 채택안 (추천)

> **토익 RC 점수가 공무원·공기업 지원, 승진, 졸업의 자격 요건인 사람에게, [서비스명]은 시험일까지 RC만 올리는 웹 학습 서비스입니다. 문항을 더 많이 주거나 강의를 더 늘리는 대신, 검수한 문항으로 '왜 틀렸는지'를 가르치고 예상 점수를 범위와 근거로 보여 줍니다.**

- 대상(자격 요건형 학습자) → 범주(RC 전용 웹 학습) → 차별점(W2 오답 이유, W3 범위형 예측) → 마감(W1 시험일까지) 순서다.
- vision.md 5장 문장에서 경쟁사 이름("산타처럼 / 해커스처럼")을 뺐다. 내부 문서로는 문제가 없지만, 이 문장은 랜딩·소개 자료로 그대로 옮겨질 가능성이 높아 처음부터 비교 대상의 이름을 넣지 않는다. 경쟁 구도는 "문항 수 경쟁 / 강의 중심"이라는 **범주**로만 표현한다.
- "취준생 일반"이 아니라 "자격 요건"을 주어로 삼은 이유: 스피킹이 자소서 어학 성적의 52.1%로 토익을 앞질렀고 [사실, personas.md S8], 토익 L&R을 계속 요구하는 곳(국가직 7급 700, 공기업, 승진 요건, 졸업 인증, 일부 기업)이 우리 1·2순위 세그먼트이기 때문이다.

### 1.2 대안 A — 마감 중심 (W1 강조)

> **시험일은 정해져 있고 시간은 하루 25분뿐인 사람에게, [서비스명]은 RC 점수만 겨냥해 남은 주 수에 맞춘 플랜과 숫자로 된 졸업 조건을 주는 서비스입니다.**

- 장점: P3(출퇴근 30분)과 P1(본 시험과 병행)에 가장 직관적이다.
- 약점: "왜 틀렸는지"(W2)가 빠져 다른 플래너형 앱과 구분이 약하다. S2 A/B에서 W1 메시지가 이기면 이쪽으로 옮긴다.

### 1.3 대안 B — 신뢰 중심 (W2·W3 강조)

> **문제를 풀어도 왜 틀렸는지, 예상 점수가 왜 그런지 모르겠다는 RC 학습자에게, [서비스명]은 모든 문항에 정답 근거와 함정 이유를 붙이고 예상 점수를 범위와 근거로 보여 주는 RC 전용 서비스입니다.**

- 장점: P2(오답 분석 정체)·P4(해설 깊이)·P3(예측 불신)에 강하다. "검수", "근거"는 대형사가 바로 따라 하기 어려운 운영 체계라 오래 간다 [추정, vision.md W2].
- 약점: 마감·짧은 학습이라는 P1의 첫 번째 동기에 덜 닿는다. 출시 후 브랜드 확장 단계(Next)에 더 적합하다.

## 3. 브랜드 톤

### 3.1 성격 3단어
**담백함 · 정직한 숫자 · 짧은 약속**

수험생에게 토익은 "넘어야 할 문턱"이다(vision.md 4장). 우리는 응원단이나 일타 강사가 아니라, 시간표를 같이 짜 주고 틀린 이유를 짚어 주는 꼼꼼한 선배처럼 말한다.

### 3.2 쓰는 법

| 원칙 | 이렇게 쓴다 | 이렇게 쓰지 않는다 |

| 존댓말, 짧은 문장 | "시험일만 알려 주세요. 플랜은 저희가 짤게요." | "여러분의 꿈을 향한 여정을 함께합니다!!" |

| 표본 한계 | 기준 전환율을 10%로 가정하면, 10%p 대 12%p 차이를 통계적으로 가리려면 군당 약 3,800명이 필요하다 [추정, 표준 표본 계산]. S2(2주)에 이 트래픽은 비현실적이다. 그래서 **S2 결과는 방향 신호로만** 쓰고, 최소 군당 300명 방문 또는 2주 중 먼저 오는 쪽에서 멈춘다. 결론은 아래 설문(vision.md W1 두 번째 검증)과 함께 판단한다 |
| 보완 | 같은 두 헤드라인으로 **검색 광고 소재 A/B**(노출 → 클릭률)를 병행한다. 노출 수가 많아 신호가 더 빨리 나온다 (예산 승인 필요) |
| 함께 보는 설문 | 등록 폼 다음 화면 선택 질문 1개: "LC는 이미 충분하고 RC가 문제다 — 동의/비동의" → vision.md 기준 50% 이상 동의. 등록자 중 20~30명을 S2 설문·인터뷰 5명으로 연결 |

**테스트 2 (선택, 설문 내) — W3 예측 표시**
- vision.md W3 검증과 동일: 같은 예측을 "RC 430" vs "RC 410~450, 근거 3줄"로 보여 주고 신뢰도(5점)와 이용 의향을 비교. 기준: 범위형이 0.5점 이상 높음. 랜딩 A/B가 아니라 설문 안에서 응답자 무작위 배정.

**테스트 3 (S3 이후, 진단 공개 시)** — CTA 문구 "무료 진단 시작" vs "내 RC 구간 확인하기", 1차 지표 진단 시작률. 이번 문서에서는 예고만.

### 6.6 목표 지표 [제안]

| 단계 | 지표 | S2 목표 | 베타 전(S6 시작) 누적 목표 | 비고 |
|---|---|---|---|---|
| 획득 | 랜딩 방문 | 600+ (A/B 군당 300) | 8,000 | SEM 소액 + 커뮤니티 + 취업센터 |
| 등록 | 방문 → 대기자 등록 | 8% 이상 | 10~12% | 업계 기준치가 없어 S2 실측으로 재설정 |
| 등록 | 대기자 수 | 50+ (설문 20~30명 확보용) | **1,000** | 베타 100명의 10배 풀 |
| 품질 | 등록자 중 세그먼트 1·2(공무원·공기업 + 승진) 비율 | 측정 | **50% 이상** | 미달 시 포지셔닝 재검토 (vision.md 7장) |
| 품질 | "RC가 문제다" 동의율 | 50% 이상 | – | vision.md W1 |
| 육성 | 대기자 이메일 오픈율 / 해지율 | – | 35% 이상 / 월 2% 이하 | S3부터 주 1회 |
| 활성 | 대기자 → 진단 완료 (진단 공개 후) | – | 40% 이상 | 이후 제품 지표(진단 완료 80%, 트랙 시작 60%)는 vision.md 8장 |
| 비용 | 등록당 비용(유료 채널) | 측정만 | 상한은 Q1 가격 결정 후 설정 | 예산은 사용자 승인 |

- 퍼널 전체: 방문 → 진단 → 가입 → (베타) 트랙 시작 → (S8~) 유료 전환 → 4주 유지. 유료 전환율·환불률 목표는 Q1·Q2(가격·환불) 결정 후 별도 문서로.

### 6.7 출시 이벤트 아이디어 (S8 무렵, 승인 전 메모)
- **대기자 우선 혜택**: 대기자에게 출시 가격의 할인이 아니라 "첫 트랙 완주 후 졸업 조건 미달 시 다음 6주 무료 연장"을 먼저 적용(roadmap Q2 (b)안 채택 시). 조건은 한 줄로.
- **"예측 vs 실제" 공개 약속**: 베타 사용자 실제 성적 입력이 100건을 넘고 목표를 달성하면 정확도를 공개하겠다고 **미리 밝혀 둔다**. 수치 자체는 기준 충족 전에 공개하지 않는다.
- 경품·추첨형 이벤트는 경품 고시·제세공과금 이슈가 있어 지양.

각 안은 헤드라인 / 서브카피 / CTA / 작은 글씨(조건 고지) 순서다.

### H2 — 오답 이유형 (V2, P2·P4 중심)

### H3 — 정직한 예측형 (V3, P3·P2 중심)

> **예상 점수, 한 숫자 대신 범위와 근거로.**

> **[ 내 RC 구간 미리 받아 보기 ]**
> <small>예측은 베타 기능이며 실제 점수와 다를 수 있습니다 · 예시 화면입니다</small>
