## 0. 가정

1. `PLAN.md`를 읽지 못했다(저장소 접근 권한 대기). 충돌이 있으면 PLAN.md가 우선한다.
2. 스프린트는 2주다. Sprint 1은 2026-10-13 시작이다.
3. 팀 규모·콘텐츠 제작 인력은 정해지지 않았다. 기간과 문항 수는 모두 **[제안]**이며 인력이 정해지면 다시 잡는다.
4. MVP는 **반응형 웹**이다. 기준 화면은 PC(1280px 이상). 모바일은 Part 5·복습·리포트가 쓸 만하면 된다.
5. MVP 트랙은 **RC 300→400, 400→450 두 개**로 시작하고 450→495는 Next에 둔다 [제안]. 이유: 페르소나 수요가 300~400대에 가장 크고(한국 평균 RC 303 [사실, personas.md]), 난이도 4~5 문항 제작·검수 비용이 가장 크기 때문이다. 단, 진단 테스트는 세 구간을 모두 판정한다. (열린 질문 Q3)

## 1. MVP 한 줄 정의

**진단 30문항으로 RC 구간과 트랙을 정하고, 시험일까지 하루 25분 플랜을 따라 검수된 문항을 웹 분할 화면에서 풀며, 정답 근거·함정 해설과 오답 원인 복습으로 약점을 고치고, 범위와 근거가 있는 RC 예측으로 진척을 확인한다.**

학습 루프: 진단 → 트랙·플랜 → 세션 풀이 → 해설 → 오답 원인 복습 → 모의고사 → 예측 → (실제 성적 입력)

### F1. RC 배치고사 (구 진단 테스트)

> 아래 구성·수용 기준은 `docs/specs/placement-and-vocab.md` 1장·4.1로 대체되었다 (2단계 고정형, A·B 각 54문항).

- 구성 [제안]: 30문항, 제한 25분. Part 5 12문항, Part 6 1세트(4), Part 7 단일 3세트(9), 이중 1세트(5). 난이도 1~5를 고르게 섞는다. 같은 구성의 A·B 두 벌을 둔다(재진단용).
- 결과: RC 추정 구간(예: "RC 330~390"), 배정 트랙, 파트별·유형 대분류별 정답률, 시간 초과 문항 수.

수용 기준
- **Given** 로그인하지 않은 방문자가 랜딩에서 "무료 진단"을 누르면 **When** 진단을 시작하면 **Then** 회원가입 없이 바로 1번 문항이 뜨고, 남은 시간과 진행률(n/30)이 보인다.
- **Given** 진단 도중 **When** 브라우저를 닫았다가 24시간 안에 다시 열면 **Then** 마지막으로 푼 문항 다음부터 이어서 풀 수 있다.
- **Given** 30문항을 모두 제출했거나 25분이 지났을 때 **When** 결과 화면이 열리면 **Then** RC 추정 구간(하한~상한), 배정 트랙(300→400 / 400→450 / 450→495 대기 안내), Part 5·6·7 정답률, 약점 상위 3개 유형(content-standard 4장 대분류 기준)이 표시된다.
- **Given** 추정 구간 하한이 450 이상일 때 **When** 결과가 나오면 **Then** "450→495 트랙은 준비 중" 안내와 대기 등록 버튼이 보이고, 400→450 트랙 고난도 세션을 대안으로 제안한다.
- **Given** 결과 화면에서 **When** 결과를 저장하려 하면 **Then** 회원가입 후 결과가 계정에 그대로 연결된다(다시 풀지 않는다).

### F2. 트랙·마감형 플랜

수용 기준
- **Given** 진단을 마친 회원이 **When** 시험 예정일, 평일 하루 학습 시간(15/25/40분), 점수가 필요한 이유(공무원·공기업 / 승진 / 기업 지원 / 졸업 / 기타)를 입력하면 **Then** 주차별 플랜(주차·파트 비중·세션 수)과 졸업 조건이 생성된다.
- **Given** 시험일까지 남은 기간이 트랙 권장 기간(6주 [제안])보다 짧으면 **When** 플랜을 만들면 **Then** "기간이 짧아 하루 N분이 필요합니다" 경고와 함께 압축 플랜 또는 다음 시험일 선택지를 보여 준다.
- **Given** 졸업 조건이 정의된 트랙에서 [제안: 300→400은 Part 5 정답률 85%, Part 7 단일 지문 정답률 70%, 모의고사 RC 예측 하한 400 이상 / 400→450은 Part 5 90%, Part 6 80%, Part 7 지문당 평균 시간 기준 이내, 예측 하한 450 이상] **When** 사용자가 대시보드를 열면 **Then** 각 조건의 현재 값과 목표 값이 숫자로 보인다.
- **Given** 사용자가 이틀 이상 세션을 건너뛰었을 때 **When** 대시보드를 열면 **Then** 남은 기간에 맞춰 플랜이 자동 재배분되고, 무엇이 바뀌었는지 한 줄로 알려 준다.
- **Given** 하루 세션을 시작하면 **When** 설정한 시간(예: 25분) 분량이 끝나면 **Then** "오늘 분량 완료"가 표시되고, 추가 학습은 선택 사항으로 제안된다.

### F3. 웹 분할 풀이 화면

수용 기준
- **Given** 화면 너비 1024px 이상에서 Part 6·7 세트를 열면 **When** 화면이 그려지면 **Then** 왼쪽에 지문(이중·삼중 지문은 탭 또는 세로 스크롤로 모두), 오른쪽에 문항이 동시에 보이고 지문과 문항이 따로 스크롤된다.
- **Given** 화면 너비 1024px 미만이면 **When** Part 6·7 세트를 열면 **Then** 지문/문항 전환 버튼이 고정 위치에 보이고 전환해도 스크롤 위치가 유지된다.
- **Given** 어떤 문항 화면이든 **When** 글자 크기 조절(최소 3단계)을 누르면 **Then** 지문·문항·해설 글자 크기가 바뀌고 다음 접속 때도 유지된다.
- **Given** 세트 안에서 **When** 이전·다음 문항으로 이동하면 **Then** 채점 전까지 답을 바꿀 수 있고, 채점 버튼과 다음 버튼은 서로 다른 위치·라벨로 구분된다 (픽토 혼동 불만 대응 [competitor-complaints.md 유형 9]).
- **Given** 문항을 풀 때 **When** 풀이가 끝나면 **Then** 문항별 풀이 시간이 기록된다(Part 7은 세트 단위 시간도 기록).
- **Given** 표준 PC 브라우저(Chrome·Edge·Safari 최신 2개 버전)에서 **When** 문항 화면을 열면 **Then** 3초 안에 상호작용이 가능하다 [가정, QA가 측정 기준 확정].

### F4. 근거 해설

콘텐츠 필드는 content-standard 2·6장을 그대로 쓴다 (`explanation_ko`, `distractor_rationale`, `key_point`, 어휘).

수용 기준
- **Given** 사용자가 문항(또는 세트)을 채점하면 **When** 결과가 나오면 **Then** 같은 화면에서 해설이 열린다. 다른 페이지 이동, 코드 입력, 재로그인이 없다 (해커스 해설 동선 불만 대응).
- **Given** Part 6·7 문항의 해설이 열리면 **When** "근거 보기"를 누르면 **Then** 지문에서 정답 근거 문장이 하이라이트되고 지문이 그 위치로 스크롤된다.
- **Given** 해설이 열리면 **When** 사용자가 오답 보기를 골랐었다면 **Then** 그 보기의 함정 이름(예: "지문 단어 반복 함정")과 틀린 이유가 맨 위에 보이고, 나머지 보기의 이유는 펼쳐서 볼 수 있다.
- **Given** 해설 하단에서 **When** "도움이 됐어요 / 아니에요"를 누르면 **Then** 응답이 `item_id`·버전과 함께 저장된다.
- **Given** 공개 상태(`published`)가 아닌 문항은 **When** 어떤 학습 화면에서도 **Then** 노출되지 않는다 (파일럿 문항은 F9 규칙과 content-standard 9장 예외에 따라 표시 후 노출).

### F5. 오답 원인 태깅 + 원인별 복습

원인 분류 [제안]: ① 문법 개념(유형 태그) ② 어휘 ③ 함정(고른 오답 보기의 함정 태그) ④ 시간(풀이 시간이 파트 중앙값의 1.5배 초과) ⑤ 찍음(사용자 선택).

수용 기준
- **Given** 사용자가 문항을 틀리면 **When** 해설이 열리면 **Then** 시스템이 추정한 원인(①~④ 중 1~2개)이 표시되고, 사용자가 한 번의 클릭으로 원인을 바꾸거나 "찍었어요"를 고를 수 있다.
- **Given** 오답이 쌓이면 **When** 오답노트를 열면 **Then** 원인별·유형 태그별로 묶여 보이고, 묶음마다 틀린 횟수와 최근 정답률이 보인다.
- **Given** 같은 원인 묶음에 오답이 3개 이상이면 **When** 다음 세션이 만들어질 때 **Then** 그 묶음의 같은 유형 태그·같은 함정 태그를 가진 **다른** 문항이 세션의 20~30%로 들어간다 [제안].
- **Given** 이미 정답을 맞힌 문항은 **When** 복습 세트를 만들 때 **Then** 7일 안에는 다시 나오지 않는다 (같은 문항 반복 불만 대응 [competitor-complaints.md 유형 4]).
- **Given** 오답노트에서 **When** 문항을 "이해함"으로 표시하면 **Then** 그 문항은 다음 복습 주기(예: 3일·7일 [제안])에 한 번 더 나온다.

### F6. RC 모의고사 1회

수용 기준
- **Given** 트랙 3주 차 이후 또는 사용자가 원할 때 **When** 모의고사를 시작하면 **Then** 실제 형식(Part 5 30, Part 6 16, Part 7 54, 75분)으로 진행되고 남은 시간이 보인다.
- **Given** 모의고사 중 **When** 문항 목록을 열면 **Then** 푼 문항·안 푼 문항·표시한 문항이 구분되어 보이고 어느 문항으로든 이동할 수 있다.
- **Given** 75분이 지나면 **When** 시간이 끝나면 **Then** 자동 제출되고 파트별 정답률, 파트별 소요 시간, 미응답 수가 나온다.
- **Given** 모의고사를 마치면 **When** 결과가 나오면 **Then** F7 예측이 갱신되고 오답은 F5 오답노트로 들어간다.

### F7. 설명 가능한 RC 예측

방식 [제안]: MVP는 정답률·유형·난이도 가중 규칙 기반 추정 + 데이터 양에 따른 범위 폭. 문항 응답이 쌓이면(content-standard 5.3, 문항당 300건) IRT로 바꾸는 것을 developer와 검토한다.

수용 기준
- **Given** 사용자가 진단을 마쳤으면 **When** 대시보드를 열면 **Then** 예측이 "RC 하한~상한"과 중앙값으로 표시되고 "베타 예측" 라벨이 붙는다.
- **Given** 예측 카드에서 **When** "근거 보기"를 누르면 **Then** 근거 문항 수, 파트별 정답률, 예측을 가장 끌어내리는 요인 상위 2개(예: "Part 7 이중 지문 정답률 40%", "Part 5 시간 초과 6문항"), 범위를 좁히는 데 필요한 추가 문항 수가 보인다.
- **Given** 근거 문항 수가 적을수록 **When** 예측을 계산하면 **Then** 범위가 넓어진다 (예: 30문항이면 ±50, 모의고사 포함 150문항 이상이면 ±25 [제안]). 범위를 일부러 좁게 표시하지 않는다.
- **Given** 직전 예측보다 중앙값이 10점 이상 바뀌면 **When** 대시보드를 열면 **Then** 바뀐 이유가 한 줄로 표시된다 ("모의고사 Part 7 결과 반영" 등) (산타 "점수가 왜 떨어지는지 모름" 불만 대응).
- **Given** 어떤 경우에도 **When** 예측을 보여 줄 때 **Then** 이를 환급·보장 조건으로 쓰지 않는다.

### F8. 실제 성적 입력

수용 기준
- **Given** 시험 예정일이 지난 사용자에게 **When** 성적 발표 예정일(시험일 + 약 10일 [가정, 확인 필요]) 이후 접속하면 **Then** 실제 RC 점수 입력 요청이 한 번 뜬다(닫기 가능).
- **Given** 사용자가 RC 점수(5~495, 5점 단위)를 입력하면 **When** 저장하면 **Then** 마지막 예측 범위와 비교 결과("범위 안 / 위 / 아래")가 보이고, 데이터가 예측 정확도 집계에 들어간다.
- **Given** 성적표 이미지 업로드는 **When** MVP에서는 **Then** 받지 않는다 (개인정보 최소 수집. 자기 보고 값만).

### F9. 문항 오류 신고

content-standard 11.2를 기능으로 옮긴 것이다.

수용 기준
- **Given** 어떤 문항·해설 화면이든 **When** "오류 신고"를 누르면 **Then** 유형(정답 이상 / 해설 이상 / 오탈자 / 기타)과 자유 입력 칸이 뜨고, `item_id`·버전·사용자가 고른 답·브라우저 정보가 자동 첨부된다.
- **Given** 신고가 접수되면 **When** 1영업일 안에 **Then** 사용자에게 접수 알림이 간다.
- **Given** 같은 문항에 "정답 이상" 신고가 3건 쌓이면 **When** 세 번째 신고가 들어오면 **Then** 그 문항은 자동으로 `suspended`가 되어 새 세션에 나오지 않는다.
- **Given** 정답이 바뀐 문항은 **When** 수정본이 공개되면 **Then** 이미 푼 사용자의 채점·오답노트·예측이 재계산되고 알림이 간다 (content-standard 11.3).

### F10. 계정·결제 (단일 상품)

상품 구조와 가격은 열린 질문 Q1·Q2에서 정한다. 아래는 어떤 안이든 지킬 바닥 기준이다.

수용 기준
- **Given** 이메일 또는 소셜 로그인 1종 [가정]으로 가입한 사용자가 **When** 다른 기기·브라우저에서 로그인하면 **Then** 기기 등록이나 재인증 없이 학습 기록이 이어진다 (영단기 기기 등록 불만 대응).
- **Given** 결제 화면에서 **When** 상품을 보면 **Then** 상품은 1개(최대 2개)이고, 가격·기간·환불 조건이 3줄 안에 같은 화면에 보인다.
- **Given** 결제한 사용자가 **When** 해지·환불을 원하면 **Then** 설정 화면에서 2번 클릭 안에 해지·환불 요청에 도달한다.
- **Given** 결제 후 7일 안이고 학습 진도가 [기준 미정]이면 **When** 환불을 요청하면 **Then** 실결제가 기준으로 처리된다 [제안, 법률 검토 필요].

## 3. 첫 문항 세트 규모 [제안]

### 3.1 산정 기준
- 트랙 기간 6주 × 주 5세션 × 세션 25분 = 30세션 [가정].
- 세션당 신규 문항 약 10~12개 + 복습 문항 (F5 규칙상 20~30%). 복습은 기존 문항 재사용이 아니라 같은 태그의 **다른** 문항을 쓰므로 신규 문항 수에 여유를 둔다.
- 난이도 분포는 content-standard 5.2 트랙 배분 목표를 따른다. 정답 위치는 한 위치 35% 이하(3.2-4).
- 지문 세트 구성은 content-standard 2.2·7.1을 따른다 (P6 = 4문항, P7 단일 2~4, 이중 5, 삼중 5).
- 트랙 간 공유: `target_track` 복수 지정이 가능하므로 난이도 3 문항 일부는 두 트랙에 같이 쓴다. 아래 수치는 공유를 빼지 않은 단순 합이다.
