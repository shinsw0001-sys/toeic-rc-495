## 0. 원칙

1. **뜻은 토익 맥락이 먼저**: 사전의 첫 뜻이 아니라 토익 비즈니스 지문에서 실제로 쓰이는 뜻을 카드 대표 뜻으로 둔다.
2. **없는 형태는 가르치지 않는다**: 파생어·콜로케이션은 표준 사전 2종 이상에서 확인된 것만 쓴다. AI가 만든 그럴듯한 형태(예: *reimbursal*)는 치명 결함이다.
3. **정답은 하나**: 어휘 체크와 퀴즈 모두 정답이 하나로 정해져야 한다. 동의어·같은 어족이 오답 보기에 들어가면 정답이 둘이 된다.
4. **단어는 사실, 목록·뜻풀이·예문은 창작물**: 개별 단어는 누구나 쓸 수 있지만, 특정 단어장의 선정·배열·뜻풀이·예문은 가져오지 않는다.
5. **자동 생성도 검수 대상**: 퀴즈는 템플릿이 만들지만, 템플릿 규칙과 표본 결과물을 사람이 검수한다.

## 1. 필수 필드와 점검 내용 (단어 카드)

필드 정의는 `content/SCHEMA.md` 어휘 카드 형식을 따른다. **필수** 하나라도 비면 검수로 넘기지 않는다.

| 필드 | 필수 | 점검 내용 |
|---|---|---|
| `word_id` | 필수 | `VC-B-####`(기초) / `VC-4-####`(400) / `VC-5-####`(450). 접두어와 `level`이 일치. 재사용 금지 |
| `lemma` | 필수 | 원형(동사 원형, 명사 단수). 구는 `phr`. 소문자(고유명사 없음). 앞뒤 공백 없음 |
| `pos` | 필수 | n / v / adj / adv / prep / conj / phr 중 1개. `meaning_ko`·예문 속 쓰임과 같은 품사 |
| `meaning_ko` | 필수 | 토익 맥락 대표 뜻 1개 (2장). 목적어가 필요하면 괄호로 보충: "(비용을) 상환하다" |
| `meaning_ko_sub` | 선택 | 보조 뜻 1개까지. 대표 뜻과 품사가 같아야 함. 뜻이 크게 다르면 카드를 나눔 |
| `examples` | 필수 | 1~2개, 각 `en`·`ko` 모두 있음 (3장) |
| `collocations` | 필수 | 2~4개, 모두 `lemma`(또는 그 굴절형)를 포함 (4장) |
| `derivatives` | 400·450 필수 | 1개 이상. 기초는 있으면 넣음. `pos`·`form` 모두 있음 (4장) |
| `confusables` | 선택 (450 권장) | `word` + `note_ko` 구별 한 줄 (5장) |
| `paraphrases` | 선택 | 대표 뜻과 같은 뜻의 표현만. 퀴즈 오답 제외 목록으로도 쓰임 |
| `type_tags` | 필수 | content-standard 4장 코드 1개 이상. 품사와 맞는 VOC 소분류 (예: v → `P5-VOC.V`) |
| `level` | 필수 | 기초 / 400 / 450 (6장) |
| `selection_note` | 필수 | 9.3 형식 |
| `author_id`, `status`, `version`, `created_at` | 필수 | 상태값·버전 규칙은 content-standard 2.1과 같음 |
| `reviewer_1_id`, `native_check_id`, `originality_check` | **[제안] 필수 추가** | 현재 SCHEMA 카드 형식에 없음. 10장 프로세스 기록용으로 문항과 같은 필드를 카드에도 추가 (SCHEMA.md 수정 필요, 콘텐츠 담당) |

참고: 문항의 `vocab[].level`(기초/중급/고급)과 카드의 `level`(기초/400/450)은 체계가 다르다. 연결 시 **기초=기초, 중급≈400, 고급≈450** 으로 대응하고, 간이 카드는 이 대응으로 레벨을 붙인다 [제안, developer 확인].

## 2. 한국어 뜻 정확성

1. **[규칙] 토익 맥락 우선**: 대표 뜻은 비즈니스 지문에서 가장 자주 쓰이는 뜻으로 고른다.
   - *address* → 대표 뜻 "(문제를) 해결하다, 다루다". "주소"는 다른 카드(n)로 나눈다.
   - *issue* (v) → "발행하다, 발급하다". *(n) 문제·쟁점*은 별도 카드.
   - *party* → "당사자, 일행" (계약서·예약 맥락). "파티"만 쓰면 결함.
2. **[규칙] 품사 일치**: 동사는 "~하다", 형용사는 "~한/~적인", 부사는 "~하게/~히", 명사는 명사형으로 쓴다. *eligible* = "자격이 있는"(○), "자격"(×).
3. **[규칙] 범위를 넓히거나 좁히지 않는다**: *tentative* = "잠정적인"(○), "확정되지 않은 임시의"(○), "불확실한"(△: 뜻이 넓어짐 → 보통).
4. **[권장] 뜻 길이** 2~20자. 쉼표로 동의 한국어 2개까지 ("상환하다, 환급하다"). 세 개 이상 나열하지 않는다.
5. **[규칙] 다의어 분리 기준**: 한국어로 옮겼을 때 서로 바꿔 쓸 수 없는 뜻이면 카드를 나눈다(placement-and-vocab 3.1-5). 같은 뜻의 뉘앙스 차이는 `meaning_ko_sub`에 둔다.
6. **검증 방법**: 검수자는 영영사전 1종 + 영한사전 1종에서 해당 뜻이 있는지 확인하고, 예문 속 쓰임이 그 뜻인지 본다. 사전 뜻풀이 문장을 그대로 옮기지 않는다(9장).

## 4. 콜로케이션·파생어 정확성

### 4.1 콜로케이션
1. **[규칙]** 2~4개. 각 항목에 표제어(또는 굴절형)가 들어 있어야 한다.
2. **[규칙]** 표준 사전 또는 코퍼스에서 확인한 조합만 쓴다. 확인 근거: 콜로케이션 사전(예: Oxford Collocations Dictionary) 또는 영영사전 예시 패턴, 또는 공개 코퍼스(COCA 등) 검색 결과가 자연스러운 빈도로 나올 것. **사전 예문 문장은 가져오지 않고 조합만 확인**한다(content-standard 8.2).
3. **[규칙]** 전치사 패턴은 정확해야 한다: *comply **with***, *be eligible **for***, *reimburse A **for** B*. 틀린 전치사는 높음.
4. **[권장]** 토익형 패턴(동사+목적어, 형용사+명사, 전치사구)을 우선. 구 길이 2~6단어.

### 4.2 파생어
1. **[규칙] 없는 형태 금지**: 모든 `form`은 표준 영영사전 **2종 이상**(예: Merriam-Webster, Oxford Learner's, Cambridge, Collins 중 2개)에 표제어 또는 run-on 형태로 실린 것만 쓴다. 1종에만 있거나 고어·희귀어는 쓰지 않는다.
2. **[규칙]** 같은 어족만 쓴다. 철자만 비슷한 다른 단어(예: *adapt*의 파생어로 *adoption*)는 치명.
3. **[규칙]** `pos`가 실제 품사와 일치. 분사형 형용사(*qualified*, *experienced*)는 사전에 형용사로 올라 있을 때만 `adj`로 넣는다.
4. **[규칙]** 표제어 자신과 같은 형태·같은 품사는 넣지 않는다.
5. **[권장]** 파생어 빈칸 퀴즈에 쓰려면 표제어 포함 **서로 다른 품사 형태 3개 이상**(목표 4개: n·v·adj·adv)이 필요하다. 3개 미만이면 그 카드는 파생어 퀴즈에서 제외되고, 결함이 아니다.
6. **[규칙]** 의미가 크게 달라진 파생어(*apply* → *appliance*)는 넣지 않는다. 퀴즈에서 "품사만 다른 같은 뜻" 전제가 깨진다.

## 5. 혼동어 (`confusables`)

1. 형태가 비슷하거나(adapt/adopt, affect/effect, persuade/pursue) 뜻이 겹쳐 토익에서 함정이 되는 단어(rise/raise, lend/borrow, especially/specially)만 넣는다.
2. `note_ko`는 한 줄(40자 이내)로 **구별 기준**을 쓴다: "adopt: 채택하다 / adapt: 맞추다·적응하다". 두 단어의 뜻만 나열해도 되지만, 둘 다 정확해야 한다.
3. 혼동어는 같은 어족이 아니어야 한다(같은 어족은 `derivatives`).
4. 혼동어 단어는 **문맥 뜻 고르기 오답 보기로 쓸 수 있다**(뜻이 다르므로). 단, 혼동어의 한국어 뜻이 정답 뜻과 겹치면 쓰지 않는다.

## 6. 레벨 배정 기준

### 6.1 기준표

| 레벨 | 대상 | 판정 기준 (둘 이상 해당) | 예 (설명용) |
|---|---|---|---|
| 기초 | RC 300 미만 / 어휘 체크 기초 미통과 | ① 중학~고1 교과 수준 일반어 ② 비즈니스 일상 고빈도(일정·주문·결제·배송) ③ 자체 문항에서 난이도 1~2 문항에만 등장 ④ 뜻이 하나로 거의 고정 | schedule, invoice, deliver, receipt |
| 400 | 300→400 | ① 공지·이메일·광고의 핵심어 ② 기본 파생어 3형 이상이 Part 5 품사 문제에 쓰임 ③ 자체 문항 난이도 2~3 ④ 일반 영어에서는 덜 쓰지만 토익에선 반복 | postpone, reimburse, eligible, renovation |
| 450 | 400→450 | ① 콜로케이션·전치사 패턴을 알아야 풀림 ② 추상 명사·형식적 표현 ③ Part 7 패러프레이즈 대상 ④ 자체 문항 난이도 3~5 | comply with, tentative, in accordance with, discrepancy |

### 6.2 판정 절차
1. 작성자와 교차 검수자가 **각자** 레벨을 매긴다.
2. 근거 세 가지(placement-and-vocab 3.1-4): (a) 자체 코퍼스 등장 문항 평균 난이도 (b) 대조용 공개 목록 순위 (c) 전문가 판단. 근거를 `selection_note`에 적는다.
3. 두 사람이 같으면 확정. 1단계 차이면 아래 경계 규칙. 2단계 차이(기초 vs 450)이거나 근거 (a)(b)(c)가 2단계 이상 엇갈리면 **콘텐츠 리드가 정한다**.

### 6.3 경계 규칙
- **B1 뜻 기준**: 단어가 아니라 **카드의 뜻**으로 매긴다. *address*(주소)=기초, *address*(해결하다)=400.
- **B2 쓰임 기준**: 단어는 쉽지만 토익 패턴이 어려우면 패턴 기준으로 올린다. *subject*(주제)=기초, *be subject to*(~의 대상이다)=450 (`phr` 카드).
- **B3 낮은 쪽 우선**: 기초/400 사이에서 결정이 안 나면 400(학습 대상에 넣는 쪽), 400/450 사이에서 결정이 안 나면 400(더 많은 수강생이 보는 쪽). 사유를 남긴다.
- **B4 데이터 우선**: 파일럿 후 자체 문항 응답에서 그 단어가 정답·핵심 오답인 문항의 실측 난이도가 쌓이면(문항 3개 이상, 각 응답 50건 이상) 그 값으로 재배정한다. 레벨 변경은 `version` +1.
- **B5 빈도 표시 금지**: "시험 빈출" 같은 표현을 레벨 근거로 화면에 쓰지 않는다(content-standard 6.2).

## 7. 어휘 체크 문항 (배치고사, 뜻 고르기 4지 + 모르겠어요)

형식: 짧은 비즈니스 구 속 표제어 **굵게** → 한국어 뜻 보기 ①~④ + ⑤ 모르겠어요. 레벨당 5문항, 폼 하나 20문항.

| # | 규칙 | 등급 |
|---|---|---|
| V1 | 표제어는 `published` 카드에서만 고른다. 같은 폼 안 중복 금지. A폼·B폼 사이에도 표제어 중복 금지 (재배치 때 재측정이 되도록) | [규칙] |
| V2 | 구(phrase)는 **2~6단어**, 자체 작성, 카드 예문을 그대로 쓰지 않음 (카드를 먼저 공부한 사람이 기억으로 맞히지 않게) | [규칙] |
| V3 | 구는 뜻을 하나로 좁혀야 하지만, **뜻을 알려 주면 안 된다**. 다른 보기를 넣어도 말이 되는 문맥이 좋다 ("**postpone** the quarterly meeting" → 연기/준비/참석/발표 모두 문법적으로 가능) | [규칙] |
| V4 | 정답 = 카드 `meaning_ko`의 대표 뜻 (짧게 줄인 형태 허용, 뜻은 같아야 함) | [규칙] |
| V5 | 오답 3개: 정답과 **같은 품사**, **같은 레벨 또는 한 단계 아래** 카드의 대표 뜻 | [규칙] |
| V6 | 오답 금지: 정답의 동의어·`paraphrases`의 뜻, 같은 어족의 뜻, 정답 뜻을 포함하거나 포함되는 뜻(상위어·하위어), 정답과 반대말 하나만 짝짓는 보기 구성(반대말로 추측 가능) | [규칙] |
| V7 | 보기 4개의 한국어 길이·어미가 비슷 (동사면 모두 "~하다") | [규칙] |
| V8 | 표제어의 다른 뜻(카드를 나눈 다의어의 다른 카드 뜻)을 오답으로 쓰지 않는다. 구 문맥과 상관없이 "알고 있는 사람"이 틀리게 된다 | [규칙] |
| V9 | ⑤ "모르겠어요"는 항상 마지막, 고정 문구. 채점은 오답 | [규칙] |
| V10 | 정답 위치(①~④)는 폼 단위로 고르게 (한 위치 35% 이하) | [규칙] |
| V11 | 레벨별 5문항의 품사 구성: 한 품사가 4개 이상이면 안 됨 | [권장] |
| V12 | 형식이 쉬운 단서를 주지 않게: 구 안에 표제어의 파생어·동의어를 함께 넣지 않음 | [규칙] |

검증: 교차 검수자와 원어민(또는 동급)이 정답을 가린 채 풀어 일치해야 한다. 어휘 체크는 RC 점수에 넣지 않지만 학습 시작 레벨을 정하므로, 정답 오류는 **치명**으로 다룬다.

## 8. 자동 생성 퀴즈 템플릿

템플릿 코드는 developer가 만들고, qa-tester는 (1) 아래 규칙이 코드에 구현됐는지 (2) 생성 결과 표본을 검수한다.

### 8.1 문맥 뜻 고르기 (Q1)
- **입력**: 카드 `examples[i].en` (표제어를 굵게 표시) → 한국어 뜻 4지선다.
- 정답 = `meaning_ko`. 오답 3개 = 7장 V5~V8과 같은 규칙으로 다른 카드에서 고른다.
- **[규칙]** 예문이 E4·E5를 통과한 카드만 이 템플릿에 들어간다.
- **[규칙]** 오답 후보에서 제외: 정답 카드의 `paraphrases`, `derivatives`의 뜻, 같은 `lemma`의 다른 카드, `meaning_ko`가 정답과 핵심 낱말을 공유하는 카드(예: "연기하다" vs "연기되다").
- **[규칙]** 사용자가 이미 본 카드의 뜻을 오답으로 우선 쓰는 것은 허용(복습 효과), 단 같은 퀴즈 세션에서 같은 오답 조합 반복은 피한다 [권장].

### 8.2 파생어 빈칸 (Q2)
- **입력**: Part 5 형식 문장에 빈칸 1개, 보기 = 같은 어족 4형(표제어 + `derivatives`). 품사 자리 문제.
- **[규칙] 문장 출처**: 카드 예문을 그대로 빈칸으로 바꾸면 정답이 표제어 품사로 고정된다. 그래서 **파생어 빈칸 전용 문장 `deriv_stem`** 을 카드에 두고 사람이 쓴다 [제안: SCHEMA 선택 필드 추가 — `{ "en": "... ------- ...", "answer_form": "reimbursement", "ko": "..." }`]. 필드가 없는 카드는 이 템플릿에서 제외한다.
- **[규칙]** 정답 형태는 `lemma` 또는 `derivatives[].form` 중 하나.
- **[규칙]** 정답 하나: 빈칸에 다른 3형을 넣으면 **문법적으로** 틀려야 한다. 같은 품사 형태가 둘(예: *competitive*·*competing* 모두 adj)이면 둘 중 하나만 보기에 넣는다. 분사(-ed/-ing)가 형용사·동사 자리 모두 가능한 경우 가장 많이 틀리므로 검수자가 직접 4개를 다 넣어 본다.
- **[규칙]** 보기 4개는 모두 4.2-1을 통과한 실존 형태. 보기를 채우려고 형태를 만들어 내지 않는다(3형뿐이면 Q2 제외).
- **[규칙]** 문장은 3장 E1·E2·E3·E6·E8을 따른다. 빈칸 단서(관사, 전치사, be동사 등)가 문장 안에 있어야 한다.
- 함정 코드는 문항과 같게 `POS_CONFUSION`.

### 8.3 템플릿 검수 방법
1. **규칙 검수**: 8.1·8.2와 13장 기계 규칙이 코드에 있는지 developer와 확인한다.
2. **표본 검수**: 레벨마다 생성 결과 **30개 이상 또는 10%** 중 큰 쪽을 무작위로 뽑아 사람이 푼다. 정답 둘 이상·오류 형태가 **1건이라도** 나오면 템플릿 원인을 고치고 전부 다시 생성한다.
3. **카드 변경 시**: 카드의 `meaning_ko`·`derivatives`·`paraphrases`가 바뀌면 그 카드가 들어간 퀴즈(정답이든 오답 후보든)를 다시 생성한다.
4. **운영 지표**: 파일럿 후 퀴즈 문항별 정답률이 95% 이상이면 오답이 너무 쉬운지, 같은 레벨 평균보다 30%p 이상 낮으면 정답 둘 의심으로 재검토한다.

## 9. 저작권 규칙 (어휘)

### 9.1 허용
- **개별 단어와 그 사실 정보**: 단어 자체, 품사, 사전에 실린 파생 형태, 일반적인 뜻(누구나 같은 뜻으로 옮길 수밖에 없는 수준, 예: postpone = 연기하다).
- 사전·코퍼스로 콜로케이션·파생어가 **존재하는지 확인**하는 것.
- 공개 라이선스 어휘 목록(NGSL·TSL·BSL 등)과의 **대조·누락 점검** (placement-and-vocab Q-P5 결정 전까지 대조만).

### 9.2 금지
1. 시판 단어장·앱(경쟁사 포함)의 **선정 목록을 그대로 또는 대부분 옮기는 것** — 순서·묶음(Day 1, Day 2…)·레벨 분류를 따라가는 것 포함.
2. 단어장·사전의 **뜻풀이 문장, 예문, 해설, 암기 팁, 혼동어 설명**을 복사·번역·가까운 바꿔쓰기하는 것.
3. 한 출판사 단어장의 같은 Day/챕터 단어를 묶어 같은 순서로 카드 묶음을 만드는 것.
4. AI 초안 프롬프트에 특정 단어장 이름을 넣거나 "○○ 단어장처럼" 요청하는 것 (content-standard 8.1-5).
5. 공개 목록을 대조용 이상으로 쓰는 것 (Q-P5 결정 전).

### 9.3 `selection_note` 작성 규칙
형식(한 줄, 세미콜론 구분):
`근거: <자체 코퍼스 N문항 | 전문가 판단 | 공개 목록 대조(목록명, 대조만)>; 레벨 근거: <6.1 판정 기준 번호>; 복사 없음: 상업 단어장·사전 뜻풀이·예문`

예: `근거: 자체 코퍼스 3문항(RC-P5-000012 외), 전문가 판단, NGSL 대조(대조만); 레벨 근거: 400-①③; 복사 없음: 상업 단어장·사전 뜻풀이·예문`

- **[규칙]** "복사 없음" 문구가 없으면 필수 필드 누락으로 본다.
- **[규칙]** 묶음 파일(`content/vocab/<레벨>_<묶음>.json`)의 카드 순서는 자체 기준(알파벳순 또는 자체 코퍼스 빈도순)으로 정하고, 묶음 파일 맨 위가 아니라 작업 기록(PR 설명 등)에 정렬 기준을 남긴다.
- **[규칙] 목록 수준 점검**: 묶음(최대 100카드)마다 qa-tester가 표제어 순서를 시판 단어장 1~2종의 목차와 비교해, **연속 10개 이상이 같은 순서**로 겹치면 보류한다.

### 9.4 독창성 점검 (카드마다)
1. 예문 특징 구절(7단어 이상) 웹 검색 — 일치하면 보류.
2. 내부 중복: 다른 카드·문항과 예문 5-gram 겹침 검사 (build_db.py 유사도 도구 재사용).
3. 결과를 `originality_check`(통과/보류 + 날짜 + 방법)에 기록 [1장 제안 필드].

## 10. 검수 프로세스와 역할

```
AI 초안 → 작성자 정리·자체 검수 → 교차 검수 → 원어민·전문가 확인 → (파일럿) → 공개
 draft      self_reviewed           cross_reviewed                       pilot     published
```

| 단계 | 담당 | 할 일 | 통과 조건 |
|---|---|---|---|
| 1. AI 초안 | 콘텐츠 담당이 AI로 생성 | 카드 필드 초안. 프롬프트에 단어장 이름 금지, 표제어·레벨·품사만 입력 | 13장 기계 검사 통과 |
| 2. 작성자 정리 | 콘텐츠 담당 (사람) | 뜻·예문·번역 다듬기, **파생어·콜로케이션 사전 2종 확인**, `selection_note` 작성 | 11장 체크리스트 자체 점검 |
| 3. 교차 검수 | 다른 콘텐츠 담당 1명 | 11장 전 항목, 레벨 독립 판정(6.2), 독창성 9.4 | 결함 없음 또는 낮음만 |
| 4. 원어민·전문가 확인 | 원어민(또는 동급) 1명 | 예문·콜로케이션 자연스러움, 예문 뜻이 하나인지, 파생형 실존 | 지적 해결 |
| 4-1. 한국어 확인 | 한국어 전문가(또는 교차 검수자 겸임) | `meaning_ko`·번역 정확성 | 지적 해결 |
| 5. 파일럿 | qa-tester + developer | 퀴즈·어휘 체크 정답률 수집 (8.3-4) | 지표 기준 통과 |
| 6. 공개 | qa-tester 승인 | 표본 재검수 | 치명·높음 없음 |

- 작성자 ≠ 교차 검수자. AI 초안은 "작성자"로 치지 않는다 — **사람 작성자가 1명 있어야** 한다.
- qa-tester는 교차 검수를 마친 카드 중 **20% 무작위 재검수**. 높음 이상이 묶음당 2건 넘으면 묶음 전체 재검수 (content-standard 9장과 같음).
- 어휘 체크 20문항(폼별)은 **전수**를 qa-tester가 다시 푼다.
- MVP 예외: 원어민 인력 확보 전(content-standard 13-1)에는 4단계를 "영어 전문가 1명 + 사전 2종 확인 기록"으로 대신할 수 있다. 이 예외는 chief-of-staff가 정하고, 인력 확보 후 공개 카드 전체에 원어민 확인을 소급한다.
- 수정: 뜻·예문·파생어를 바꾸면 3단계부터 다시. 오탈자는 교차 검수자 확인만.

## 11. 카드별 체크리스트

**A. 필드·형식**
- [ ] 필수 필드 모두 있음, `word_id` 접두어와 `level` 일치
- [ ] `pos`가 뜻·예문 쓰임과 같음, `type_tags`가 품사와 맞음

**B. 뜻**
- [ ] 대표 뜻이 토익 비즈니스 맥락 뜻이다 (영영·영한 사전 각 1종 확인)
- [ ] 한국어 어미가 품사와 맞다, 뜻 범위가 넓거나 좁지 않다
- [ ] 다의어면 카드가 나뉘어 있다

**C. 예문**
- [ ] 자체 작성, 웹 검색 일치 없음
- [ ] 가상 회사·인물만, 미국식 철자, 금지 주제 없음
- [ ] 8~25단어 한 문장, 표제어 1회, 카드와 같은 뜻·품사
- [ ] 문맥으로 뜻이 하나로 정해짐
- [ ] 번역이 정확하고 표제어 번역이 `meaning_ko`와 맞음

**D. 콜로케이션·파생어**
- [ ] 콜로케이션 2~4개, 전치사 패턴 정확, 사전·코퍼스 확인함
- [ ] 파생어는 모두 사전 2종에 있음, 같은 어족, 품사 정확
- [ ] (400·450) 파생어 1개 이상

**E. 혼동어·패러프레이즈**
- [ ] 혼동어는 다른 어족이고 구별 한 줄이 정확
- [ ] 패러프레이즈는 대표 뜻과 같은 뜻

**F. 레벨·저작권**
- [ ] 레벨을 독립 판정했고 6.3 경계 규칙을 따름
- [ ] `selection_note`가 9.3 형식이고 "복사 없음"이 있음
- [ ] 사전·단어장 뜻풀이·예문을 옮기지 않음

**G. 퀴즈 적합성** (해당 시)
- [ ] Q1: 예문이 E4·E5 통과
- [ ] Q2: 서로 다른 품사 형태 3개 이상, `deriv_stem`이 있으면 4형을 모두 넣어 보고 정답 하나 확인

## 12. 결함 심각도

content-standard 11.1의 등급·조치·기한을 그대로 쓴다. 어휘에서의 예:

| 등급 | 어휘 예시 |
|---|---|
| 치명 | 존재하지 않는 파생어·콜로케이션, 대표 뜻 오역(뜻이 바뀜), 어휘 체크·퀴즈 정답 오류 또는 정답 둘(동의어·같은 어족 오답), 다른 어족을 파생어로 넣음, 사전·단어장 예문·뜻풀이 복사, 시판 목록 순서 복제, 실존 기업·인물 예문 |
| 높음 | 토익 맥락이 아닌 뜻을 대표로 둠, 틀린 전치사 패턴, 예문 속 쓰임이 카드 뜻·품사와 다름, 예문 번역 오역, 레벨 2단계 오배정, 다의어 미분리로 퀴즈가 애매함 |
| 보통 | 예문이 문맥 단서가 약함, 길이 범위 이탈, 뜻 범위가 약간 넓음, 레벨 1단계 어긋남, 콜로케이션이 어색하지만 틀리진 않음, `selection_note` 형식 불완전 |
| 낮음 | 오탈자(뜻 변화 없음), 괄호·쉼표 서식, 보조 뜻 누락 |

치명은 즉시 `suspended`하고, 그 카드가 들어간 퀴즈·어휘 체크 문항도 함께 내린다. 어휘 체크 정답 오류면 해당 폼 응시자의 어휘 레벨을 다시 계산한다.

## 13. 기계 검사 규칙 (build_db.py 구현용)

developer가 `db/build_db.py`의 `load()`에 `content/vocab/*.json` 검사를 추가할 때의 목록. **E** = 빌드 실패(오류), **W** = 경고(리포트만).

| ID | 대상 | 규칙 | 등급 |
|---|---|---|---|
| VR01 | 카드 | 필수 필드 존재: word_id, lemma, pos, meaning_ko, examples, collocations, type_tags, level, selection_note, author_id, status, version, created_at | E |
| VR02 | 카드 | `word_id` 정규식 `^VC-(B\|4\|5)-\d{4}$`, 접두어↔level (B=기초, 4=400, 5=450) 일치 | E |
| VR03 | 카드 | `word_id` 전체 유일 | E |
| VR04 | 카드 | `pos` ∈ {n,v,adj,adv,prep,conj,phr}; `level` ∈ {기초,400,450}; `status` ∈ content-standard 상태값 | E |
| VR05 | 카드 | (lemma, pos, meaning_ko) 조합 중복 없음. 같은 (lemma, pos)가 둘 이상이면 W (다의어 분리 확인) | E / W |
| VR06 | 카드 | `lemma`가 소문자, 앞뒤 공백 없음, `phr`이 아니면 공백 없음 | E |
